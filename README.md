# Поиск дубликатов файлов: сравнение по содержимому и формирование отчёта

## О задании

Разработайте консольную программу на Python, которая рекурсивно обходит выбранную папку, находит файлы с одинаковым содержимым и сохраняет отчёт в JSON. Названия и расширения файлов при сравнении не учитываются.

**Время:** примерно 8–10 часов, включая изучение материалов, разработку, тестирование, документацию и видео.

## Сценарий использования

В папке пользователя находятся документы и их копии. Некоторые копии переименованы или лежат в разных вложенных папках. Программа должна показать группы дубликатов и объём, который занимают лишние копии.

Программа только анализирует файлы. Удаление, перемещение и изменение найденных файлов в задание не входят.

## 1. Запуск

Реализуйте интерфейс командной строки, например:

```bash
python -m duplicate_finder --directory ./sample_data --output ./report.json
```

Аргументы:

| Аргумент | Назначение |
| --- | --- |
| `--directory` | Папка для поиска, обязательный аргумент |
| `--output` | Путь к итоговому JSON-отчёту, обязательный аргумент |

При успешном выполнении выводите краткую сводку и путь к отчёту. Для некорректного пути или невозможности записать отчёт выводите понятную ошибку без необработанного traceback.

Коды завершения:

- `0` — обход завершён, отчёт записан, ошибок чтения не было;
- `1` — неверные аргументы, недоступна исходная папка или не удалось записать отчёт;
- `2` — отчёт записан, но часть файлов или вложенных папок не удалось прочитать.

## 2. Обход папки

- Рекурсивно обработайте обычные файлы, включая файлы без расширения и скрытые файлы.
- Символические ссылки на файлы и папки пропускайте. Это исключает повторный обход и зацикливание.
- Пустые файлы учитывайте: два пустых файла являются дубликатами.
- Файл отчёта исключайте из поиска, если он расположен внутри исходной папки. Это правило действует и для существующего отчёта при повторном запуске.
- Если отдельный файл или вложенная папка недоступны, добавьте ошибку в отчёт и продолжите обработку остальных файлов.
- Если файл исчез во время обработки, также зарегистрируйте ошибку и продолжите работу.

Допущение: содержимое доступных файлов не меняется во время сканирования. Обнаружение одновременного редактирования и специальные случаи жёстких ссылок не входят в обязательную часть. Каждый обычный путь считайте отдельным файлом.

## 3. Поиск дубликатов

Реализуйте алгоритм в два этапа:

1. Сгруппируйте файлы по размеру в байтах. Файл с уникальным размером не требует чтения содержимого.
2. Для файлов из групп размером от двух вычислите SHA-256. Совпадение размера и хеша считайте признаком одинакового содержимого в рамках задания.

Читайте данные блоками, например по 64 КиБ. Не загружайте файл целиком в оперативную память.

В итоговые группы включайте только файлы с успешно вычисленным хешем. В каждой группе должно быть не менее двух путей. Одинаковые имена и расширения сами по себе не означают совпадение содержимого.

## 4. Отчет

Сохраняйте JSON в UTF-8. Пути файлов внутри отчета должны быть относительными к исходной папке, с разделителем `/`.

Пример структуры; вместо поясняющего значения `sha256` программа должна записать настоящий хеш:

```json
{
  "scanned_files": 5,
  "duplicate_groups": 1,
  "extra_copies": 2,
  "potential_savings_bytes": 2048,
  "groups": [
    {
      "size_bytes": 1024,
      "sha256": "здесь строка SHA-256 из 64 шестнадцатеричных символов",
      "files": ["archive/copy.txt", "docs/original.txt", "other.txt"]
    }
  ],
  "errors": []
}
```

Значения полей:

- `scanned_files` — число обычных файлов, для которых удалось получить размер, даже если позднее произошла ошибка чтения; ссылки и файл отчёта не учитываются.
- `duplicate_groups` — количество групп дубликатов.
- `extra_copies` — сумма `количество файлов в группе − 1` по всем группам.
- `potential_savings_bytes` — сумма `размер файла × (количество файлов в группе − 1)` по всем группам. Это расчёт по логическим размерам файлов, без учёта особенностей файловой системы.
- `groups` — найденные группы с размером, хешем и списком путей.
- `errors` — список объектов с полями `path` и `message`. Для ошибки обхода корневой папки можно использовать путь `.`.

Сортируйте пути внутри каждой группы по алфавиту, а группы — по первому пути в группе. Список ошибок также сортируйте по пути. При неизменных входных данных и одинаковых условиях доступа отчёт должен воспроизводиться без изменений.

Если дубликатов нет, запишите пустой `groups` и нули в полях количества групп, лишних копий и потенциальной экономии. Пустая исходная папка — корректный вход.

## 5. Требования к коду

- Python 3.11 или новее.
- Для основной программы достаточно стандартной библиотеки: `pathlib` или `os`, `hashlib`, `argparse`, `json`.
- Разделите обход, вычисление хеша, группировку и сохранение отчета на отдельные функции.
- Закрывайте открытые файлы, в том числе при ошибках.
- Для тестов используйте `pytest` или `unittest`.
- Веб-интерфейс, база данных, Docker и внешние API не требуются.

## 6. Проверка решения

Подготовьте автоматические тесты на временных папках:

| Сценарий | Ожидаемый результат |
| --- | --- |
| Одинаковое содержимое, разные имена и папки | Файлы попадают в одну группу |
| Одинаковые имена, разное содержимое | Файлы не считаются дубликатами |
| Одинаковый размер, разные байты | Файлы не считаются дубликатами |
| Три одинаковых файла | Одна группа, две лишние копии, экономия равна двум размерам файла |
| Два пустых файла | Одна группа, одна лишняя копия, экономия 0 байт |
| Пустая папка или только уникальные файлы | Пустой список групп, корректные счетчики |
| Файлы с кириллицей и пробелами в именах | Успешный поиск и корректные пути в JSON |
| Ошибка чтения одного файла | Ошибка отражена в отчете, остальные файлы обработаны, код завершения `2` |
| Вместо папки передан файл или несуществующий путь | Понятная ошибка, код завершения `1` |
| Повторный запуск с отчетом внутри исходной папки | Отчет исключен из поиска, результат не меняется |
| Файл с уникальным размером | Функция вычисления хеша для него не вызывается |

Ошибку чтения моделируйте подменой функции чтения или вычисления хеша: тест не должен зависеть от прав администратора и особенностей операционной системы. Для проверки оптимизации можно отслеживать вызовы функции вычисления хеша.

GitHub-репозиторий со следующими материалами:

1. Исходный код программы.

5. Краткий отчет: алгоритм, зачем нужна группировка по размеру, результаты тестов и известные ограничения. Можно добавить отдельный раздел в README.
6. Видео на 3–5 минут: демонстрация поиска, пояснение отчета, обработка ошибки и запуск тестов.

Не включайте в репозиторий личные документы и большие наборы данных: для демонстрации достаточно искусственно созданных небольших файлов.

## 8. Критерии оценивания

- Программа запускается по инструкции.
- Находит копии по содержимому независимо от имени и расположения.
- Корректно рассчитывает количество лишних копий и потенциальную экономию.
- Читает файлы блоками и не вычисляет хеш для уникальных размеров.
- Продолжает работу после ошибки чтения отдельного файла.
- Не изменяет исходные файлы.
- Проходит перечисленные автоматические проверки и формирует воспроизводимый JSON-отчет.
